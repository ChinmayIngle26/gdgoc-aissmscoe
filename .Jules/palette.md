## 2024-03-24 - Floating Action Button Stack Alignment
**Learning:** Fixed absolute positioning for floating elements causes scaling and reflow issues when animated (e.g. Framer Motion hover states), resulting in inconsistent spacing or elements covering each other. Hardcoded offsets (e.g., `bottom-16`, `bottom-32`) are brittle to content changes. Additionally, when copy-pasting repetitive elements like social buttons, structural elements like `aria-label` often remain unchanged, creating a11y regressions (e.g. all three social buttons saying "Join Whatsapp Group").
**Action:** Always wrap floating stacked elements in a flex container (e.g., `flex-col items-end`) rather than using per-element `absolute` offsets. Apply `pointer-events-none` to the fixed flex container and `*:pointer-events-auto` to its children so the invisible parent hit box doesn't obscure the actual page content. Thoroughly audit cloned code blocks for unique attributes such as `aria-label`, empty `alt` attributes, and `aria-hidden` attributes on purely decorative icon children. Always pair `whileHover` with `whileFocus` alongside Tailwind `focus-visible` outlines for full keyboard accessibility.
