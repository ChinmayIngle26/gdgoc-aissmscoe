## 2025-01-24 - Accessible Expandable Floating Action Buttons
**Learning:** Expanding action buttons utilizing Framer Motion's `whileHover` can become inaccessible for keyboard navigation. Additionally, floating button containers block interaction on underlying elements. Screen readers vocalize purely decorative icons inside interactive buttons with `aria-label` attributes.
**Action:** Pair `whileHover` with `whileFocus` to ensure focusability for keyboard users. Combine with Tailwind's `focus-visible:ring-2 focus-visible:outline-none` for explicit visible focus indicators. Apply `pointer-events-none` to fixed containers with `*:pointer-events-auto` applied to child elements to make only the buttons interactive. Append `alt=""` and `aria-hidden="true"` to strictly decorative graphics where contextual `aria-label`s are already defined.

## 2025-01-24 - Keyboard Accessibility for Hover-Revealed Elements
**Learning:** In interactive components like the `Member` card, interactive elements (social links) are revealed using Tailwind's `group-hover:translate-y-0`. This hides them visually during keyboard tabbing, as tabbing to the inner links does not trigger `group-hover`, leaving the focused elements invisible beneath the layout boundary. Moreover, icon-only links lacked contextual `aria-label`s.
**Action:** Always pair `group-hover` with `group-focus-within` on the container to ensure the layout shifts and reveals elements when its children receive focus. Apply contextual `aria-label`s (e.g., `aria-label={`${member.name}'s GitHub`}`) and `focus-visible:ring-2 focus-visible:outline-none` to the child `<a>` or `<Link>` tags, and add `aria-hidden="true"` to purely decorative icon child elements.
