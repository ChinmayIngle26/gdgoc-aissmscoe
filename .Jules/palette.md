## 2025-02-12 - Keyboard Accessible Framer Motion Interactions
**Learning:** Found a recurring pattern where interactive Framer Motion components (like expanding social buttons) used `whileHover` for visual feedback but lacked equivalent keyboard support. This renders the dynamic behavior completely inaccessible to non-mouse users. Also, floating components frequently omitted visual focus indicators and security attributes (`rel="noopener noreferrer"`) for external links.
**Action:** When working with Framer Motion, strictly pair `whileHover` with `whileFocus` to ensure interactions are parity for keyboard navigation. Always combine this with Tailwind's `focus-visible` utilities (e.g., `focus-visible:ring-2 focus-visible:outline-none focus-visible:ring-offset-2`) to provide explicit, reliable focus indicators without impacting mouse users.
